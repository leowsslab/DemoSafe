# DemoSafe 資安檢查與使用界線

檢查日期：2026-10-04（Asia/Taipei）。範圍是目前原型的原始碼、本機 API 非破壞性檢查、檔案留存、相依套件版本比對及核心回歸測試。這不是滲透測試或資安認證。

## 結論

本版已加入每次啟動的隨機憑證、瀏覽器工作階段、嚴格同源檢查、影格嵌入限制，以及可確認的任務刪除。適合以內建虛構素材展示與人工覆核流程；仍不能自動保證去識別成功，也不應直接當作多人或公開網路服務。

最新 96 項自動測試已在獨立乾淨環境通過，包括驗證失敗、媒體存取、重新啟動失效、取消後實際工作尚未結束、刪除路徑邊界、匯出／刪除並發競態、評估完整性及交付包排除規則。完整指令、警告與原始碼雜湊記於 `reports/test_summary_final_v2.json`；較早的 86 項結果保留在 `reports/test_summary_v2.json`。這些測試驗證列出的行為，不代表已找出所有漏洞。

## 本版已確認的保護

- 服務實測只監聽 `127.0.0.1:8765`。啟動器在該服務成功啟動後，以 URL fragment 交付隨機憑證；前端在第一次驗證請求前移除 fragment。憑證不寫入伺服器存取日誌或交付包。
- `POST /api/session` 必須帶正確啟動憑證與完全相符的 Origin。成功後取得 HttpOnly、SameSite=Strict、僅限目前 hostname 的 cookie。重啟即使保留瀏覽器 cookie，也會使舊工作階段與啟動憑證失效。這是單人本機存取控制，沒有使用者帳號系統。
- 除了工作階段交換端點，所有 `/api/` 路由都要求驗證，包括任務內容、原片、預覽、輸出與報告。匿名讀取回覆 401。內建虛構樣本與前端靜態檔案可公開讀取；使用者上傳目錄沒有靜態掛載。
- 修改資料的請求比對完整 scheme、hostname 與 port。外部網站、不同本機 port、缺少 Origin、`null` Origin 均回覆 403；異常 Host 也回覆 403。沒有開放跨來源讀取的 CORS 標頭。
- 回應含 `CSP frame-ancestors 'none'`、`X-Frame-Options: DENY`、`nosniff`、`no-referrer` 與 `no-store`。腳本只允許同源；樣式仍允許 inline，以支援現有畫面尺寸與進度更新。
- 公開任務 JSON 複製資料後移除 `event.text`，不改動內部 OCR 分析。匯出報告也不含偵測文字原文。原片與原始預覽本身仍包含來源內容，登入後可以存取。
- 刪除要求實際 Future 已結束；「取消」或畫面顯示完成不會略過這項檢查。目錄必須是該任務的精確路徑，拒絕越界與 link/junction。匯出排程與刪除使用同一把鎖，避免刪除後又以舊參照排程工作；已有可重現該競態的回歸測試。刪除不會掃除其他任務或歷史資料夾。
- 輸入上限為 100 MB、60 秒、1920×1080、30 fps；路徑、手動遮罩與明確覆核決策有測試。FFmpeg 以參數陣列啟動，不使用 `shell=True`。前端敏感標籤以 `textContent` 寫入。
- 應用程式正常 OCR 路徑沒有雲端模型或外部上傳 API 呼叫。參賽旁白由參賽者另外提供，DemoSafe 不產生旁白，也不將匯入素材或 OCR 文字交給語音服務。

## 實測紀錄與查詢範圍

原始機器紀錄為 `reports/security_review_v2.json`；早期的 `reports/security_review.json` 是修補前的歷史快照，不能用來描述本版。驗證包含匿名 API 401、合法工作階段 200、不同本機 port／外部／缺少 Origin 403，以及已驗證且正確 Origin 的不存在樣本回覆 404。最後一項確認請求確實進入路由，沒有只測到前置阻擋。

OSV 批次查詢已完成，30 個已安裝的 Python 執行期套件名稱與版本沒有回傳已知漏洞匹配。**這只是該次套件版本查詢的結果，不等於沒有風險或沒有漏洞。** 查詢未涵蓋 FFmpeg/OpenCV 所含所有原生元件、未知漏洞、應用程式邏輯與網路外連行為。查詢只送公開套件名稱與版本，沒有送素材、OCR 文字或憑證。

留存快照中的原片皆經 SHA-256 比對，與內建虛構素材相符；檔案數量、容量與快照時間詳見原始紀錄。這是時間點紀錄，後續操作可能改變數量。重啟不會自動刪除這些檔案。

新版已在乾淨安裝環境完成真實瀏覽器操作：自動建立工作階段、取消、事件選取、人工遮罩、無效時間拒絕、匯出、下載及重新匯出。紀錄為 `reports/validation_ui_v2.json`。UI 刪除測試驗證了確認畫面與保留任務；永久刪除和處理程序結束前的阻擋則由 API／自動測試驗證，兩者沒有混稱。

## 仍存在的風險與界線

| 風險 | 證據與界線 | 使用與後續處理 |
|---|---|---|
| 漏判後誤以為安全 | 開發集 `dev_019` 的憑證未被偵測，20 個影格未遮罩；同模型重掃也漏判。 | 必須檢查原片和輸出，必要時補手動遮罩。新字型、壓縮與真實介面需新增獨立評估，不能用已看過的保留集調整後再稱為新證據。 |
| 本機存取控制的界線 | 隨機憑證阻擋未持有憑證的 API 存取，但不隔離同一作業系統上的惡意程式。Cookie 的 hostname 範圍不以 TCP port 分隔。 | 不把嚴格 Origin 誤稱為隔離其他本機服務；已有檔案或瀏覽器存取權的惡意程式仍可能取得素材或工作階段。 |
| 原始素材留存 | 檔案沒有應用層加密、自動到期或自動清除歷史資料夾。重啟會清空索引，舊資料仍在磁碟上。 | 完成工作後使用刪除；停止服務後再人工檢查不需要的歷史資料夾。檔案刪除不是磁碟安全抹除，既有下載或備份也不會一併消失。 |
| 解碼器與資源耗用 | OpenCV/FFmpeg 與 OCR 在本機執行，缺少獨立受限程序及完整逾時機制；取消採合作式檢查。 | 檔案大小限制不能保證惡意媒體安全。先使用可信素材；陌生檔案可能耗用 CPU／記憶體或觸發原生解碼器問題。 |
| 第三方元件與未知漏洞 | OSV 的 30 套件查詢沒有匹配，但不是完整原生元件清單或弱點研究。 | 繼續追蹤套件與原生函式庫更新，保留版本／模型雜湊，不宣稱「零漏洞」。 |
| 受控測試與真實資料差距 | 自動測試和合成素材證明部分可重現行為，沒有涵蓋任意錄影或所有並發時序。 | 分享前人工確認輸出；UGen300 實機與真實使用情境仍需獨立驗證。 |

刪除與媒體播放同時發生時，作業系統仍可能回報檔案使用中，此時 API 回覆 409，關閉預覽後可重試。刪除不能撤回已開始傳送或已下載的內容。

## 明確未驗證

- 沒有進行惡意影音 fuzzing、全面滲透測試、網路封包監測或第三方稽核。
- 沒有證明所有第三方解碼器在所有格式下都不會連線；「程式沒有雲端上傳呼叫」不等於網路隔離。
- 未確認 BitLocker、作業系統修補狀態、其他本機程式或瀏覽器擴充套件的安全性。
- 沒有建立公開網路、多使用者或互不信任本機服務的部署邊界。

本次沒有對外發布或修改外部服務。提交原始碼時應排除 `data/jobs`、環境目錄、工作階段 cookie、啟動 URL 與 OS 暫存的 launch-info 檔案。
