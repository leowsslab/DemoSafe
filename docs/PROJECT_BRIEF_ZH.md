# DemoSafe｜分享支援錄影前的敏感文字覆核

更新：2026-10-05。隊名及公開名稱已確認為 **DemoSafe**。定位為單人參賽、工作場域 AI／Battlefield Lightning 輕量運算組／Global Online Track。這是準備方向，不代表已報名或晉級。

## 一句話提案

讓支援工程師在分享操作錄影前，找到短暫出現的敏感文字、確認遮罩範圍，並檢查實際匯出的結果。

主要情境是工程師要把問題重現影片交給同事、客戶或供應商，畫面卻可能短暫出現 email、電話、憑證或內部專案關鍵字。DemoSafe 在本機協助檢查；最後是否分享仍由使用者決定。

## 作品的實際價值

| 使用者的工作 | DemoSafe 提供的協助 |
|---|---|
| 找到影片裡哪一瞬間出現敏感內容 | 檢查每個解碼影格，列出有時間與位置的發現。 |
| 判斷什麼需要隱藏 | 逐項保留／遮蔽；支援人工補上指定時間的矩形遮罩。 |
| 確認遮罩真的寫入輸出 | 用原影格位置製作實心遮罩，再掃描匯出後的像素。 |
| 說明此次分享前做了哪些處理 | 提供不含偵測明文的處理報告，保留原檔與獨立輸出。 |

差異在這套可追溯的錄影覆核流程，不宣稱發明 OCR 或自動打碼。不把畫面乾淨的範例、合成資料或 AI 模擬操作當成真實客戶採用證據。

## 目前完成與限制

已有 CPU OCR、事件時間定位、人工決定、人工遮罩、靜音匯出、前後對照和再次掃描。乾淨環境的完整瀏覽器流程已驗證，包括取消、保留／遮蔽、人工框選、下載、過期輸出提示及重新匯出。v3 已重新設計介面與兩份簡報，並以真實操作素材和你提供的旁白完成 178 秒影片、中英雙字幕及無字幕備份；詳細檢查範圍見 `REVIEW_RELEASE_V3.md`，等待本人最終審閱。

舊版受控合成測試為開發集 23/24 個事件、原保留集 24/24 個事件。新強化資料兩組各 12 支影片均已完成：開發集 20/24 個事件至少偵測到一次（83.33%），237/336 個標註敏感影格區域完整遮罩（70.54%）；保留集則為 18/24 個事件（75.00%）與 231/336 個區域（68.75%）。影格區域分母包含漏判或只遮到部分的區域，不能換成已選遮罩的成功比例。兩組各有 6/6 支乾淨負樣本、零額外事件誤報，僅限這批受控素材。完整性 gate 與 969 項獨立複核均通過，來源見 `reports/evaluation_v2_results.json` 與 `reports/evaluation_v2_independent_review.json`。兩代資料分開報告，不宣稱真實客戶錄影準確率。

保留集曾在完成 10 支後因本人要求關機而暫停，恢復後以未變動的程式與資料完成最後兩支，屬同一輪凍結評估。每秒一格回放在 15 個相位上的保留集事件召回平均為 43.33%，範圍 25.00% 至 50.00%；逐格是 75.00%。這是重用 OCR 結果的回放比較，不是實測加速倍數。

舊版深色等寬憑證與新版終端機關鍵字都有漏判。新版保留集試算表 C 更漏判持續 2 秒的憑證及 1 秒的自訂關鍵字，只完整遮罩 11/56 個標註影格區域，但同一 OCR 再掃描仍回報通過、零發現。因此「沒有再發現支援的模式」不等於保證沒有個資或機密。完整失敗案例仍保留於 `reports/evaluation_v2_results.md`。

目前不辨識任意人名、人臉、任意商業機密或聲音內容。影片輸出移除整條音軌，不做語音理解或選擇性消音。細字、壓縮、低對比、遮擋與未知格式會降低可靠性。

UGen300 尚未實機驗證；先確認配發 USB 或 M.2 型號，再使用對應的官方 runtime 與匹配 OCR HEF，詳見 [硬體路線](HARDWARE_ROADMAP.md)。不承諾尚未測得的加速倍數。

## 初賽的說服重點

- **可行性：**展示實際 App 操作、可重現安裝、明確錯誤處理和完整輸出。
- **創新：**證明短暫曝光的時間定位、逐項覆核、逐影格遮罩及輸出檢查如何連成實用流程。
- **實用價值：**以支援工程師分享問題重現錄影為單一情境；節省時間、付費意願與需求規模仍是待驗證假設。
- **硬體必要性：**量測各階段耗時，說清楚 OCR 是否為瓶頸，以及 UGen 要改善什麼；不以硬體規格取代實測。

本階段不承諾獲獎或晉級機率；參賽隊數、其他作品與評審結果未知。
